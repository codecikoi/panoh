# Madat (репозиторий `codecikoi/panoh`) — контекст проекта

Этот файл читает Claude Code в начале каждого чата из этой папки. Здесь суть проекта, принятые решения, текущее состояние и план следующих этапов. README.md и docs/DEPLOY.md — публичная документация на английском, этот файл — рабочие заметки для Зоира и Claude.

## Что это

Telegram-бот семейных финансов, позиционируется как «семейный помощник». Живёт в группе «муж + жена + бот» (или в личке). Люди пишут обычным языком: «продукты 150к», «получил зарплату 9 млн», «напомни в пятницу заплатить за садик», «кредит 2 млн каждое 15 число», «оплатили кредит», «в декабре подарок на свадьбу 3 млн», «лимит на продукты 3 млн», «копим на отпуск 10 млн к июлю». Бот записывает расходы и доходы, ставит напоминания, ведёт регулярные платежи, запланированные расходы, лимиты по категориям и копилки, по `/summary` присылает сводку месяца по категориям со сравнением с прошлым месяцем, свободными деньгами месяца и советами. Первого числа сводка приходит сама.

План: сначала тест вдвоём (Зоир и жена), потом дашборд, потом публичный запуск по подписке через Telegram Stars.

Бот: `@panoh_fam_bot`. Продукт в коде и в сообщениях называется **Madat** (до 2026-10-13 был Budgie: игра слов budget + budgie, волнистый попугайчик; переименован по решению Зоира). Папка проекта на диске `madat` (переименована 2026-10-13), репозиторий на GitHub — **panoh** (не переименовывать, решение Зоира).

**Название Madat утверждено окончательно 2026-10-19, к выбору не возвращаться.** Смысл: «мадад» = «помощь» в арабском, персидском, узбекском и таджикском; два слога, читается одинаково везде, как обращение к боту не путается с обычной речью. Проверены и отклонены: Famo (заняты все домены и боты, в римском сленге «давай сделаем»), Charos/Charoz (в греческом Charos — олицетворение смерти, в хинди charas — гашиш, плюс популярное женское имя ломает триггер), Oiko, Tanga, Barakat, Hamyon, Tilla, Daftar, Sharepot (уже есть такое приложение), Twopenny («грошовый»), PennyPair, Pursely, HomePurse и др. Для публичного запуска свободны (на 2026-10-19) домены **madat.app** и **getmadat.com** (madat.com занят) и боты **@madatappbot**, **@madat_family_bot**, @heymadatbot (@madatbot занят).

Непонятность названия с первого взгляда закрывается подписью: при старте бот сам выставляет через Bot API отображаемое имя «Madat — семейный помощник» (с 2026-10-19, решение Зоира: чтобы ощущался частью семьи, а не сервисом; до этого «семейный бюджет»), короткое описание и описание на 30 языках (`setProfile` в `apps/bot/src/bot/commands.ts`, строки `bot.name` / `bot.short_description` / `bot.description` в локалях, лимиты 64/120/512 проверяет тест). Пишется только то, что отличается от текущего, потому что `setMyName` у Telegram жёстко ограничен по частоте; недописанное повторится при следующем старте. Ручной `/setname` в BotFather больше не нужен: бот перезапишет его при старте.

## Стек и структура (решено 2026-10-12, «стек за тобой»)

pnpm-монорепо, TypeScript, Node 22+:

```
apps/bot        grammY-бот + планировщик напоминаний + HTTP (webhook, /health, /internal/tick)
apps/api        Hono REST API для дашборда, авторизация через Telegram initData
apps/dashboard  Telegram Mini App (React + Vite), только просмотр
packages/core   схема БД (Drizzle), миграции, ИИ-слой, сервисы, i18n, триггеры, валюты, даты
```

- БД: Postgres через Drizzle. Локально без Postgres работает встроенный PGlite (`DATABASE_URL` пустой → файлы в `data/pglite`). PGlite однопроцессный: бот и API одновременно на нём не запустить, для этого `docker compose up db`.
- ИИ: Anthropic SDK. `claude-haiku-5-5` разбирает каждое помеченное сообщение (structured outputs, `messages.parse` + zod), `claude-opus-5-5` пишет инсайты к сводке (с серверным fallback `fallbacks: "default"`). Цифры считает код, модель только текст — так в советах не появляются выдуманные суммы.
- Сборка: tsup в один файл на приложение, Docker-образы без node_modules. PGlite исключён из бандла (dev-only).
- Тесты: vitest. core — чистые функции + интеграционные на PGlite в памяти; bot — сквозной сценарий с фейковым Telegram-транспортом (`client.fetch`) и замоканным разбором; api — через `app.request()`.
- Сетевая особенность Мака Зоира: системный DNS (VPN-туннель, резолвер 172.31.1.50) подменяет `api.telegram.org` на приватный IP. В боте есть автообход через DNS-over-HTTPS (`apps/bot/src/network.ts`) и опция `TELEGRAM_PROXY`. В облаке это не нужно.

## Ключевые решения

| Тема | Решение |
|---|---|
| Что бот читает в группе | Только помеченные сообщения: префикс `+`, обращение по имени в начале сообщения (`мадат …` / `madat …`, а также `мадад` / `madad`, любой регистр, имя отрезается перед разбором; список `BOT_NAMES` в `packages/core/src/triggers.ts`), упоминание, ответ боту, ключевые слова, сумма с валютой. Остальное не обрабатывается и не хранится. Privacy mode у бота выключен (Group Privacy → off в BotFather). |
| Подтверждения | Каждая запись подтверждается ответом с кнопками ✏️/🗑, реакция ✍ на сообщение. При низкой уверенности бот спрашивает «записать?». Правки — ответом на подтверждение («не 150, а 115», «категория транспорт»). |
| Языки | База английский. 30 локалей в `packages/core/src/i18n/locales`: en/ru/uz написаны вручную, остальные 27 машинный перевод. Новые строки: вручную в en/ru/uz, остальные 27 Claude переводит **сам в чате** (решение Зоира 2026-10-24: скрипт `pnpm locales:translate` ходит в API на ключе Зоира и тратит его деньги — запускать только по его явной просьбе; режимы `--missing`, `--keys=a,b`, `--force`). Тест проверяет ключи и плейсхолдеры. Ключевые слова-триггеры есть для всех 30 языков. |
| Валюты | Базовая валюта семьи, пересчёт по курсам open.er-api.com раз в сутки. Непересчитанные суммы показываются отдельно. |
| Время напоминаний | Если дата есть, а времени нет — берётся `households.reminderHour` (по умолчанию 9), в подтверждении пометка «время по умолчанию» и кнопка 🕒 с выбором часа. Настройка в `/settings` → «🕒 Время напоминаний». Тот же час используется для напоминаний о регулярных платежах. |
| Значения по умолчанию для семьи | В `.env`: `DEFAULT_LOCALE=ru`, `DEFAULT_CURRENCY=UZS`, `DEFAULT_TIMEZONE=Asia/Tashkent`. Для языков, привязанных к одной стране (uz, kk, tr, de …) валюта и пояс подбираются автоматически; для ru/en/es/fr/pt/ar берутся из env. |
| Планирование (2026-10-19) | Запланированный расход (`plans`): дата или только месяц (тогда последний день месяца + `dateApproximate`, дату правят ответом на подтверждение). В день плана напоминание `plan_due` с кнопками ✅ Оплатили / ⏱ Завтра / 🗑 Отменить; «купили подарок 2.8 млн» закрывает план (payment_done) и пишет план/факт. Удаление такой траты возвращает план. Лимиты (`budgets`): месячный лимит на категорию, строка 🎯 в подтверждении каждой траты, ⚠️ от 80%, 🚨 при превышении. Копилки (`goals`): цель + срок, взнос = расход категории savings с `goalId`, темп = (цель − накоплено до этого месяца) / оставшиеся месяцы. |
| Правки и уточнения (2026-10-19, после первого теста) | Каждая правка пишется в `record_edits` (поля до/после), история передаётся модели вместе с записью, поэтому «верни как было» работает. Если сообщение не ответ, модели передаётся последняя запись (до 30 мин). Новый вид ответа `clarify`: модель коротко переспрашивает или отвечает на вопрос о записи, только по фактам из контекста; при прямом обращении к боту без записи (привет, спасибо, «оставь») тоже отвечает по-человечески вместо «Не нашёл, что записать». Сумма, отличающаяся от прежней в 1000+ раз без указанной валюты, не применяется, а подтверждается кнопками Да/Нет (`fix:amt` / `fix:keep`). Правка, которая ничего не меняет, получает честный ответ и 🤔, а не 👌. Голое число 1–31 в ответ на план без точной даты — это день; прошедший день этого месяца — уточнение, а не тихий перенос на следующий месяц. |
| Своё имя помощника (2026-10-24) | Каждая семья может переименовать помощника (`households.assistant_name`, null = Madat): `/name Кексик`, `/name reset`, кнопка в `/settings`, или словами («Мадат, теперь тебя зовут Кексик» → вид ответа модели `rename`). Бот откликается на новое имя в начале сообщения так же, как на встроенные `BOT_NAMES` (они продолжают работать), называет себя им в приветствиях и ответах модели. Отображаемое имя в профиле Telegram общее для всех и не меняется. Идея Зоира: персонализация поможет продажам. Проверка имени: 1–32 символа, начинается с буквы (`normalizeAssistantName`). |
| Какие данные храним (2026-10-24) | Решение Зоира: не храним текст сообщений и имена людей. Удалены `transactions.raw_text`, `users.first_name`, `users.username`; у личных чатов `households.title` = null (раньше туда писалось имя). Остаются Telegram ID, язык, название группы (для выбора семьи в дашборде) и сами записи. Последние 4 сообщения чата для контекста модели живут только в памяти процесса. Бэкапы только на сервере (решение Зоира, внешнюю копию не делаем). |
| PDF-отчёт (2026-10-24) | `/report` (кнопки: эта/прошлая неделя, этот/прошлый месяц), `/report 2026-09`, `/report 01.10–15.10`, словами («отчёт за прошлую неделю» → вид ответа `report_request` с `date`/`date_to`), кнопка «📄 PDF» под каждой сводкой, в том числе под автосводкой 1-го числа (файлы всем автоматически не шлём — решение Зоира). Неделя — пн–вс. В отчёте: плитки доходы/расходы/остаток с изменением к прошлому периоду такой же длины, полоса долей (5 крупнейших категорий + «Прочее» штриховкой; цвета — слоты 1–5 проверенной палитры skill `dataviz`), таблица категорий, доходы, полный список операций по дням; только для месячного: «деньги месяца», лимиты, копилки, планы, советы (из кэша инсайтов). Рендер: HTML (`apps/bot/src/report/html.ts`, без скриптов, CSP без сети, всё пользовательское экранируется) → headless Chromium (`report/pdf.ts`, процесс на отчёт, сеть отрезана прокси-заглушкой). Очередь по одному отчёту, 10 отчётов в час на семью, повтор того же отчёта без изменений данных отправляется по `file_id` без рендера. Образ бота с Chromium и шрифтами Noto ≈ 1,7 ГБ. Предпросмотр вёрстки: `pnpm --filter @madat/bot report:preview /tmp/r.pdf ru [week]` (локальный Chrome). |
| Свободные деньги месяца | Решение Зоира: считаем только уже полученный доход, будущую зарплату не учитываем («этих денег у нас нет»), остаток прошлых месяцев тоже не переносим. Свободно = доход месяца − потрачено − впереди (неоплаченные платежи месяца, открытые планы до конца месяца включая просроченные, недостающий взнос в копилки). Платёж, добавленный после его дня в этом месяце, не считается. Код: `computeOutlook` в `packages/core/src/services/planning.ts`. |
| Хостинг | Решено 2026-10-24: VPS **Vultr**, Frankfurt, Shared CPU `vc2-1c-2gb` (1 vCPU, 2 ГБ, 55 ГБ, 10 $/мес), Ubuntu 26.04 LTS, IP `140.82.39.106`, автобэкапы Vultr отключены (решение Зоира). Бот и Postgres в `docker compose` (`deploy/compose.prod.yml`), long polling, наружу открыт только SSH (ufw), вход только по ключу `~/.ssh/id_ed25519_madat` (хост `madat` в `~/.ssh/config`). Отклонены: Railway («серьёзное место»), Google Cloud (дорого и сложно для теста), Convex (пришлось бы переписать бэкенд), Cloudzy (отчёт Halcyon 2023 о хостинге хакерских групп), Contabo (слабая производительность и поддержка). Cloud Run (`docs/DEPLOY.md`) — вариант на будущее при росте. |
| Репозитории | Один монорепо вместо трёх репо (общая схема БД и ИИ-слой). При желании разделяется через `git subtree split`. |

## Текущее состояние на 2026-10-19

Этап 1 готов и работает:

2026-10-13: переименование Budgie → Madat (пакеты `@madat/*`, `app.name` в 30 локалях, docker-compose, docs) и триггер по имени `мадат`/`madat` с пунктом в групповом приветствии на всех 30 языках.

Предыдущее изменение (напоминания без времени + настройка часа) прошло многоагентное ревью (3 ревьюера + 6 проверяющих): все 6 находок подтверждены и исправлены — флаг `reminders.defaultTime` (миграция 0001), перенос даты сохраняет явное время, смена часа/пояса переносит запланированные напоминания, выбор часа не воскрешает выполненные и не принимает мусор, кнопки подтверждения снимаются после срабатывания.

2026-10-19: имя «семейный помощник» (профиль бота, описания на 30 языках обновлены) и планирование: запланированные расходы, лимиты по категориям, копилки, блок «свободно / не хватает» в сводке, команды `/plans` `/budgets` `/goals`, API `GET /api/households/:id/plans` и `/planning`. Миграция 0002_planning. Живая проверка промпта на новых фразах (ru/uz) прошла.

Известные мелочи и долги:
- `setMyCommands` для 30 языков занимает ~20 с при старте, делается в фоне.
- Планировщик на каждом тике перебирает все семьи (нормально для теста, для публики нужен индекс/батчи и блокировка при нескольких инстансах).
- Голосовые сообщения и фото чеков не поддерживаются (этап 3).
- Лимиты в прогноз «свободно» не входят (только платежи, планы, копилки). Общего лимита на месяц нет, только по категориям.
- Изъятие из копилки не поддерживается; цель закрывается кнопкой 🗑 или «отмени».
- Кнопка «Открыть дашборд» появляется, только когда заданы `DASHBOARD_URL` (личка, web_app-кнопка) и/или `DASHBOARD_TME_LINK` (группа, ссылка `t.me/<bot>/<app>?startapp=<householdId>_<month>`).

## Этап 2: дашборд (Telegram Mini App)

Решено 2026-10-24 (Зоир): React + Vite, только просмотр (без правки записей), экспорт только PDF, главный экран — месяц с итогами, долями категорий, свободными деньгами, сравнением с прошлым месяцем: что выросло, что снизилось (включая исчезнувшие категории), что появилось нового.

Сделано (`apps/dashboard`, ≈ 74 КБ gzip):
- вкладки: Месяц (плитки расходы / доходы / свободно или не хватает, «что изменилось», полоса долей + список категорий с отметкой «новое», наблюдения и советы, кнопка «📄 PDF-отчёт за месяц»), Операции (по дням, фильтр по категории, «ждёт подтверждения»), Планы (запланированные расходы, регулярные платежи, напоминания), Цели (лимиты с ⚠️/🚨, копилки);
- тема и цвета из Telegram (`--tg-theme-*`), светлая и тёмная; цвета категорий — проверенные слоты палитры skill `dataviz` для обеих тем; язык семьи — строки `dash.*` приходят из `GET /api/i18n/:locale` (в бандл не попадают 30 словарей);
- выбор семьи, если их несколько; переключатель месяцев; `startapp=<householdId>_<YYYY-MM>` из группы, `?month=` из лички;
- PDF из дашборда: `POST /api/households/:id/report` → бот (`POST /internal/report`, `INTERNAL_TOKEN`) присылает отчёт в чат семьи (Chromium есть только в образе бота);
- в сводку добавлены `newCategories` и `droppedCategories`.

Разработка: `PGLITE_DIR=./data/pglite-demo pnpm --filter @madat/api demo:seed` (демо-семья для пользователя 42), API на демо-базе (`PGLITE_DIR=... BOT_TOKEN=dev PORT=8081 pnpm dev:api`), `pnpm --filter @madat/dashboard dev` → `http://localhost:5173/?debugUser=42&tab=month|operations|plans|goals`. Vite запускать из `apps/dashboard` (в корне лежит Vite 7 от vitest, плагин React требует Vite 8). ## Деплой (VPS Vultr, с 2026-10-24)

```bash
deploy/deploy.sh          # rsync рабочей копии в /opt/madat и docker compose up -d --build (сборка ~20 с)
deploy/deploy.sh logs     # логи бота
deploy/deploy.sh status   # контейнеры и health
ssh madat                 # root на сервере
```

- `.env` на сервере (`/opt/madat/.env`, права 600) свой: BOT_TOKEN, ANTHROPIC_API_KEY, DEFAULT_*, AI_*, POSTGRES_PASSWORD. `deploy.sh` его не трогает. Значения не выводить в чат.
- Бэкап: `deploy/backup.sh` → `/usr/local/bin/madat-backup`, cron 03:30 UTC, дампы в `/var/backups/madat`, хранятся 14 дней. Только на сервере, внешней копии нет (решение Зоира 2026-10-24; автобэкапы Vultr тоже отключены).
- Подвох сборки: tsup/esbuild переименовывал класс `AbortSignal` → `AbortSignal2`, а `node-fetch` проверяет имя класса; бандл бота вис на `bot.init()` без единого запроса. Лечится `keepNames: true` в tsup-конфигах (стоит в bot и api). Тесты и `pnpm dev:bot` этого не ловят, потому что идут из исходников: после правок сборки проверять сам бандл.
