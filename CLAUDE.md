# Budgie (репозиторий `codecikoi/panoh`) — контекст проекта

Этот файл читает Claude Code в начале каждого чата из этой папки. Здесь суть проекта, принятые решения, текущее состояние и план следующих этапов. README.md и docs/DEPLOY.md — публичная документация на английском, этот файл — рабочие заметки для Зоира и Claude.

## Что это

Telegram-бот семейных финансов. Живёт в группе «муж + жена + бот» (или в личке). Люди пишут обычным языком: «продукты 150к», «получил зарплату 9 млн», «напомни в пятницу заплатить за садик», «кредит 2 млн каждое 15 число», «оплатили кредит». Бот записывает расходы и доходы, ставит напоминания, ведёт регулярные платежи, по `/summary` присылает сводку месяца по категориям со сравнением с прошлым месяцем и советами. Первого числа сводка приходит сама.

План: сначала тест вдвоём (Зоир и жена), потом дашборд, потом публичный запуск по подписке через Telegram Stars.

Бот: `@panoh_fam_bot`. Продукт в коде и в сообщениях называется **Budgie**; репозиторий на GitHub называется **panoh**. Переименование не делали, решение за Зоиром.

## Стек и структура (решено 2026-10-12, «стек за тобой»)

pnpm-монорепо, TypeScript, Node 22+:

```
apps/bot        grammY-бот + планировщик напоминаний + HTTP (webhook, /health, /internal/tick)
apps/api        Hono REST API для дашборда, авторизация через Telegram initData
apps/dashboard  (этап 2, ещё нет) Telegram Mini App
packages/core   схема БД (Drizzle), миграции, ИИ-слой, сервисы, i18n, триггеры, валюты, даты
```

- БД: Postgres через Drizzle. Локально без Postgres работает встроенный PGlite (`DATABASE_URL` пустой → файлы в `data/pglite`). PGlite однопроцессный: бот и API одновременно на нём не запустить, для этого `docker compose up db`.
- ИИ: Anthropic SDK. `claude-haiku-5-5` разбирает каждое помеченное сообщение (structured outputs, `messages.parse` + zod), `claude-opus-5-5` пишет инсайты к сводке (с серверным fallback `fallbacks: "default"`). Цифры считает код, модель только текст — так в советах не появляются выдуманные суммы.
- Сборка: tsup в один файл на приложение, Docker-образы без node_modules. PGlite исключён из бандла (dev-only).
- Тесты: vitest. core — чистые функции + интеграционные на PGlite в памяти; bot — сквозной сценарий с фейковым Telegram-транспортом (`client.fetch`) и замоканным разбором; api — через `app.request()`.
- Сетевая особенность Мака Зоира: системный DNS (VPN-туннель, резолвер 172.31.1.50) подменяет `api.telegram.org` на приватный IP. В боте есть автообход через DNS-over-HTTPS (`apps/bot/src/network.ts`) и опция `TELEGRAM_PROXY`. В облаке это не нужно.

## Ключевые решения

| Тема | Решение |
|---|---|
| Что бот читает в группе | Только помеченные сообщения: префикс `+`, упоминание, ответ боту, ключевые слова, сумма с валютой. Остальное не обрабатывается и не хранится. Privacy mode у бота выключен (Group Privacy → off в BotFather). |
| Подтверждения | Каждая запись подтверждается ответом с кнопками ✏️/🗑, реакция ✍ на сообщение. При низкой уверенности бот спрашивает «записать?». Правки — ответом на подтверждение («не 150, а 115», «категория транспорт»). |
| Языки | База английский. 30 локалей в `packages/core/src/i18n/locales`: en/ru/uz написаны вручную, остальные 27 машинный перевод (написаны Claude в сессии, скрипт `pnpm locales:translate --force` перегенерирует через API). Новые строки добавляются сразу во все 30 файлов, тест проверяет ключи и плейсхолдеры. Ключевые слова-триггеры есть для всех 30 языков. |
| Валюты | Базовая валюта семьи, пересчёт по курсам open.er-api.com раз в сутки. Непересчитанные суммы показываются отдельно. |
| Время напоминаний | Если дата есть, а времени нет — берётся `households.reminderHour` (по умолчанию 9), в подтверждении пометка «время по умолчанию» и кнопка 🕒 с выбором часа. Настройка в `/settings` → «🕒 Время напоминаний». Тот же час используется для напоминаний о регулярных платежах. |
| Значения по умолчанию для семьи | В `.env`: `DEFAULT_LOCALE=ru`, `DEFAULT_CURRENCY=UZS`, `DEFAULT_TIMEZONE=Asia/Tashkent`. Для языков, привязанных к одной стране (uz, kk, tr, de …) валюта и пояс подбираются автоматически; для ru/en/es/fr/pt/ar берутся из env. |
| Хостинг | Railway отклонён («серьёзное место»). Рекомендация: Google Cloud Run (бот и API как два сервиса) + Cloud SQL Postgres, Cloud Scheduler дёргает `/internal/tick` раз в минуту. Инструкция в `docs/DEPLOY.md`. |
| Репозитории | Один монорепо вместо трёх репо (общая схема БД и ИИ-слой). При желании разделяется через `git subtree split`. |

## Текущее состояние на 2026-10-13

Этап 1 готов и работает:
- разбор сообщений, подтверждения, правки, отмена, напоминания, регулярные платежи, «оплатили», сводка с инсайтами, автосводка 1-го числа, настройки, ключевые слова, 30 языков, API для дашборда;
- живая проверка промпта (`pnpm simulate`) на русском, английском и узбекском прошла без ошибок;
- бот запускался локально: `nohup ./node_modules/.bin/tsx --env-file=.env apps/bot/src/index.ts`, pid в `data/bot.pid`, лог в `data/bot.log`, остановить `kill $(cat data/bot.pid)`. Два экземпляра одновременно нельзя (Telegram отдаёт обновления одному);
- в облако ещё ничего не развёрнуто. База сейчас только локальный PGlite.

Последнее изменение (напоминания без времени + настройка часа) прошло многоагентное ревью; подтверждённые находки исправлены или перечислены в последнем коммите.

Известные мелочи и долги:
- `setMyCommands` для 30 языков занимает ~20 с при старте, делается в фоне.
- Планировщик на каждом тике перебирает все семьи (нормально для теста, для публики нужен индекс/батчи и блокировка при нескольких инстансах).
- Голосовые сообщения и фото чеков не поддерживаются (этап 3).
- Кнопка «Открыть дашборд» появляется, только когда заданы `DASHBOARD_URL` (личка, web_app-кнопка) и/или `DASHBOARD_TME_LINK` (группа, ссылка `t.me/<bot>/<app>?startapp=<householdId>_<month>`).

Команды:

```bash
pnpm install
pnpm dev:bot            # бот, long polling, миграции автоматически
pnpm dev:api            # API на PORT из .env
pnpm test               # все тесты
pnpm typecheck
pnpm build              # tsup-бандлы в apps/*/dist
pnpm simulate "текст"   # разбор на живой модели
pnpm db:generate        # новая миграция после правки packages/core/src/db/schema.ts
```

## Этап 2: дашборд (Telegram Mini App)

Цель: по кнопке «📊 Открыть дашборд» в одно касание открывается экран, где «всё чётко и ясно по категориям»: куда и сколько ушло, сравнение с прошлым месяцем, где просело и где много уходит, ближайшие платежи, советы.

Что уже готово под него:
- `apps/api`: `GET /api/me`, `GET /api/households/:id/summary?month=YYYY-MM` (сводка + инсайты), `/transactions?month=`, `/reminders`, `/recurring`. Авторизация: заголовок `Authorization: tma <initData>` (проверка подписи в `packages/core/src/telegram/initData.ts`). Для локальной разработки вне Telegram: `X-Debug-User: <telegram id>` (только не в production). CORS через `DASHBOARD_ORIGIN`.
- Формат сводки: `MonthlySummary` в `packages/core/src/services/summary.ts` (категории с долями и дельтами, topGrowth/topDrop, biggest, avgPerDay/projected, upcomingPayments, openReminders, unconverted). Инсайты: `{highlights[], tips[], mood}`.
- Бот уже умеет показывать кнопку при заданных `DASHBOARD_URL` / `DASHBOARD_TME_LINK`.

Рекомендуемое решение (обсудить перед стартом):
1. **Стек:** Vite + React + TypeScript, Telegram Web Apps SDK (`window.Telegram.WebApp` или `@telegram-apps/sdk`), цвета из `themeParams` (светлая и тёмная тема), лёгкие графики (например Recharts). Не Flutter Web: тяжёлая первая загрузка в WebView.
2. **Экраны:**
   - Месяц: расходы/доходы/остаток, дельта к прошлому месяцу, кольцевая диаграмма по категориям, список категорий с долей и изменением, «где выросло / где упало», средний расход в день и прогноз.
   - Операции: список по дням с фильтром по категории, пометка ожидающих подтверждения.
   - Платежи и напоминания: ближайшие платежи с датами, открытые напоминания.
   - Советы: блок инсайтов и советов.
   - Переключатель месяцев, выбор семьи, если пользователь состоит в нескольких.
3. **Интеграция с Telegram:** в BotFather `/newapp` создать Mini App (короткое имя), URL дашборда; прямая ссылка `https://t.me/panoh_fam_bot/<app>?startapp=<householdId>_<month>` для групп; параметр `startapp` разбирать на фронте.
4. **Хостинг:** статика на Cloud Run (nginx) или Firebase Hosting / Cloudflare Pages; API на Cloud Run с `DASHBOARD_ORIGIN`.
5. **Порядок работ:** каркас `apps/dashboard` в монорепо → экран «Месяц» на данных `/summary` → остальные экраны → подключить `DASHBOARD_URL`/`DASHBOARD_TME_LINK` в боте → деплой.
6. Перед графиками Claude должен загрузить skill `dataviz`.

Вопросы к Зоиру перед этапом 2: React или Svelte; нужен ли ввод/правка операций прямо в дашборде (тогда в API добавляются PUT/DELETE); нужен ли экспорт (CSV); что считать главным экраном.

## Этап 3: публичный запуск (набросок)

- Онбординг: `/start` создаёт семью, ссылка-приглашение для партнёра, выбор валюты/пояса/языка в первом диалоге.
- Подписка через Telegram Stars (регулярные списания в боте), бесплатный тариф с лимитами (например, 50 записей в месяц без инсайтов).
- Режим приватности для публики: только помеченные сообщения (уже так) плюс возможность отдельной группы «финансы».
- Голосовые сообщения (транскрипция), фото чеков (vision), экспорт.
- Эксплуатация: Postgres, блокировки планировщика при нескольких инстансах, мониторинг, ограничение частоты запросов к модели на семью.
